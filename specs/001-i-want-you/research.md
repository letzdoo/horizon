# Research: School Export Reports Addon

## Odoo Report Framework Decision
**Decision**: Use Odoo's built-in report_xlsx framework with custom report classes
**Rationale**:
- Integrates seamlessly with Odoo's reporting system
- Provides Excel generation capabilities via xlsxwriter
- Follows OCA patterns used in existing school_reporting_xlsx module
- Supports menu actions and wizard interfaces
**Alternatives considered**: Direct xlsxwriter usage, pandas Excel export
**Rejected because**: Would not integrate with Odoo UI/UX patterns and security model

## CSV File Handling Approach
**Decision**: Direct file system access to export directory with validation
**Rationale**:
- CSV files are already generated by existing system
- Simple file reading reduces dependencies
- Allows for explicit validation and fail-fast error handling
- Consistent with constitution's fail-fast principle
**Alternatives considered**: Database storage of CSV data, API endpoints for data
**Rejected because**: Adds unnecessary complexity and doesn't leverage existing export files

## Module Structure Pattern
**Decision**: Follow school_reporting_xlsx structure with separate report classes per CSV type
**Rationale**:
- Proven pattern in existing codebase
- Each report type has unique formatting requirements
- Allows for independent testing and maintenance
- Follows OCA single responsibility principle
**Alternatives considered**: Single report class with parameters, wizard-based selection
**Rejected because**: Would create overly complex single class and reduce maintainability

## Error Handling Strategy
**Decision**: Explicit validation with detailed error messages, no fallbacks
**Rationale**:
- Aligns with constitution's fail-fast development principle
- CSV validation ensures data integrity before processing
- Clear error messages help administrators identify issues
- Prevents silent data corruption or incomplete reports
**Alternatives considered**: Default values for missing data, partial report generation
**Rejected because**: Violates fail-fast principle and could produce misleading reports

## Testing Approach
**Decision**: Unit tests for each report class, integration tests for CSV validation
**Rationale**:
- Covers both individual report generation and file handling
- Allows testing with mock CSV data
- Ensures error handling paths are covered
- Meets constitution's 80% coverage requirement
**Alternatives considered**: Manual testing only, end-to-end tests only
**Rejected because**: Insufficient coverage and difficult to maintain

## French Language Support
**Decision**: UTF-8 encoding throughout with explicit French character handling
**Rationale**:
- Educational data contains French terminology and special characters
- Odoo framework supports UTF-8 natively
- Excel format preserves character encoding
- Critical for institutional reporting requirements
**Alternatives considered**: ASCII with character replacement, locale-specific handling
**Rejected because**: Would corrupt educational terminology and violate data integrity requirements
